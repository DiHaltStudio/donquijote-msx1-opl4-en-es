# Building the bilingual MSX-DOS edition

## Requirements

| Tool / input | Purpose |
|---|---|
| Python 3.10 or later | Extract, localize and pack resources |
| Pillow (`requirements.txt`) | Convert the DiHalt logo to SCREEN 2 |
| GNU Make | Build targets |
| sjasm 0.42c | Assemble the Z80 sources; not sjasmplus |
| Original Side A and Side B TSX files | Original engine, BASIC program, pictures and Spanish text |
| Original drawing cache | Import from the release or regenerate as described below |
| Tectonic | Optional: rebuild manual PDFs |
| openMSX and an MSX1 machine ROM | Optional: regenerate drawing caches |

No DOS kernel, COMMAND.COM, Nextor kernel, speech model or emulator is needed for the ordinary `make` build. Supply your own MSX-DOS/Nextor installation when running the game.

## Original inputs

Create `third_party/original/` and place the two TSX files there. Their names can differ; the builder identifies each by SHA-256. It accepts these editions:

| Side | TSX edition | SHA-256 |
|---|---|---|
| A | Don Quijote (1987), Spanish, Side A, RUN'CAS-', v0.8.4b | `0008e44465922950cece8b9afedf3073af6e183e55e9f4a9c482efd12ad8bc2e` |
| B | Don Quijote (1987), Spanish, Side B, RUN'CAS-', v0.8.4b | `9b3c3519b55dd92d48e8c185dc89e6f8ded32afcafd8264a009d0d03dab24100` |

`assets/originals.json` also records the full original filenames. The extractor reads the TSX KCS records without modifying the supplied files. The build uses MENU, SLOT, SCREEN, the full QUIJ1 block, BLOQUE and QUIJ2 from each side. It excludes the short cassette loader. Fixed-width patches retain the addresses used by the original engine.

### Drawing inputs: quick route

Download and unpack the playable release, then run:

```sh
make import-graphics RELEASE_DIR=/path/to/unpacked/package
```

You can also pass its `SD/` directory. This copies only `VRAM.DAT` and `VRAM.IDX` to the ignored `third_party/graphics/` directory, after checking their hashes. It does not import executables, speech or operating-system files. These two files are original-derived picture inputs; every executable and other runtime file is built from this repository and your tapes.

### Drawing inputs: regenerate from the tapes

Install openMSX and provide the Philips VG-8020 machine ROM through its normal system-ROM configuration. Then run:

```sh
make graphics OPENMSX=openmsx
```

This is an **explicit emulator-based asset preparation step**, separate from `make`. It extracts both tapes, loads each original side, and executes its drawing routines over the BASIC DATA compositions. It collects only VRAM 0000h–0FFFh and 2000h–2FFFh, deduplicates identical pictures, and imports the result into `third_party/graphics/`. The resulting files must match `assets/graphics.json`. `OPENMSX` can also name a launcher executable.

There are 34 compositions, 33 distinct pictures and 270,336 bytes of picture data. The useful index is 2,048 bytes; its runtime form is padded to 16,384 bytes. No cartridge build is involved.

## Quick start

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
make PYTHON=.venv/bin/python SJASM=sjasm
make release PYTHON=.venv/bin/python VERSION=2.0
```

The original and graphics directories can be changed with `ORIGINAL_DIR=...` and `GRAPHICS_DIR=...`. A missing or different input stops the build with an explanatory message. The build reads the originals; it does not patch them in place.

## Targets

| Target | Result |
|---|---|
| `make` | Four executables in `build/SD/`; refresh the 31-file SD package and ZIP |
| `make extract` | Intermediate cassette records under `build/extracted/` |
| `make import-graphics RELEASE_DIR=...` | Local drawing inputs from the downloaded package |
| `make graphics` | Drawing inputs regenerated by openMSX from the two tapes |
| `make release VERSION=2.0` | Rebuild and refresh the same bilingual directory, ZIP and SHA256SUMS under `release/` |
| `make manual TECTONIC=tectonic` | English and Spanish PDF manuals |
| `make check` | Source-file and package-input checks |
| `make clean` | Remove build intermediates; retain original inputs and releases |

The tracked manual PDFs can be packaged without installing Tectonic. To edit them, change `docs/manual/content-en.tex` / `content-es.tex`, then run `make manual`. Layout and diagrams are in `manual.tex`; artwork is in `assets/` beside it.

## Build stages

1. Identify and extract the two original TSX files by hash.
2. Read the original drawing cache and its index.
3. Convert the DiHalt source logo; pack its sample data and event stream.
4. Expand each included compressed PCM bank. Check unit lengths and hashes, deduplicate score sequences, and build runtime indexes.
5. Build Spanish game blocks with the DOS, picture and speech patches.
6. Repack the English translation, nouns and verbs inside the original engine's reserved regions; build its patched game blocks.
7. Assemble trampoline, resident and loader for each language and graphics option. The MSX2 build also patches the loading images, packs its editable indexed PNGs and assembles the VDP command driver.
8. Assemble QMENU.COM and the two versioned BAT launchers; merge all four sets into one SD directory. Shared filenames must have identical contents.
9. Package the runtime files, both manuals, technical documentation and attribution.

Speech data in `assets/speech/` is an editable prepared bank, not a compiler dependency on a remote service. `catalog.json` describes units by PCM offset, sample count and hash; message entries contain their lookup key and a hexadecimal score. The gzip contains signed 8-bit, 8 kHz PCM with eight zero bytes on either side of each unit. Editing translation text also requires matching speech lookup keys and audio; translating text alone does not update narration.

## Outputs and distribution

`build/SD/` and the package's `SD/` contain the same 31 files. No operating-system files are bundled. Copy all 31 into one folder for DOS2/Nextor or the root for DOS1. The two languages share BRAND.DAT, VRAM.DAT/IDX and SC5.DAT/IDX. The graphics options share each language's speech banks, indexes and scores. QUIJOTE.BAT and QUIXOTE.BAT select Q1ES/Q1EN or Q2ES/Q2EN.COM.

The ZIP, generated directory and checksum list are release attachments, not source files to commit. `third_party/`, `build/`, generated listings and release payloads are ignored by Git. Manual PDFs in `docs/manual/` remain part of the source repository.

## Editable MSX2 graphics

`assets/msx2/` contains indexed PNGs with palette index 0 black and 15 white.
`pictures.json` stores the exact VDP palette bytes and both room tables.
`tools/native_game.py` packs the pictures and derives the original font from
the separately supplied tape; no preassembled driver or game executable is
needed. The driver sources are in `src/msx2/`. It uses HMMM/HMMV for text
and HMMC plus hidden-page switching for room pictures.
